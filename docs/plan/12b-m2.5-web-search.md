# M2.5 — Web Search (stub)

**Status:** not planned in detail. This document records why the milestone exists
and what is already known, so the session that plans it properly does not start
from scratch.

**Goal:** let a message be answered with grounded, cited web results.

**Why it is its own milestone.** It was raised during M1.7 and deliberately not
folded in. Three reasons, all verified against OpenRouter's docs on 2026-08-03:

1. **It is not a model capability.** Web search works on _any_ model on
   OpenRouter, via `:online` appended to the slug or a `plugins: [{ id: "web" }]`
   entry on the request. Nothing in the model catalog gates it — in particular
   `supported_parameters: ["web_search_options"]` (14 models) is **not** a
   capability flag; it only carries `search_context_size` for native search.
   Gating on it would hide a feature that works on all 325 models.
2. **It is mostly a rendering problem.** Results come back as `annotations` of
   type `url_citation`, each with `url`, `title`, `content`, `start_index` and
   `end_index`, standardised by OpenRouter across native and Exa results. That is
   a new message-part renderer, not a toggle.
3. **It needs persistence to exist first.** Citations are message metadata. M2
   makes messages persistent; building this afterwards means citation storage is
   designed once rather than twice. Hence M2.5, not M1.8.

**Known before planning starts:**

- Engines: `native` (Anthropic, Google, OpenAI, Perplexity, xAI), `exa` (the
  fallback for everything else), plus `firecrawl`, `parallel`, `perplexity`.
  Unspecified means native-if-available, else Exa.
- Cost is real and per-request: Exa $0.005/request for up to 10 results then
  $0.001 each; Parallel $0.001; Perplexity $0.005; native is provider passthrough.
  A user-visible cost story is part of this milestone, not an afterthought.
- The plugin takes `max_results`, `search_prompt`, `include_domains` and
  `exclude_domains`, with per-engine differences in whether include and exclude
  can be combined.

**Open questions for the planning session:**

- Do OpenRouter's `url_citation` annotations survive Mastra's stream layer, and in
  what shape? Verify against the installed packages — do not assume.
- Is web search a per-message toggle, a per-model setting in M1.7's
  `SettingsPicker`, or an agent-level decision? It is not per-model in nature, so
  the settings picker may be the wrong home despite being the obvious one.

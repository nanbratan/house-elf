# M1.5 — Choosing the Model

**Goal:** Pick the model from the composer, per message, from a server-side allowlist
of Anthropic models — and use the same allowlist to give the E2E suite a scripted
fake model so the auto-scroll tests can run the real pipeline instead of a
hand-written stub.

**Why this exists:** [01-decisions.md](01-decisions.md) D6 originally set model IDs
through environment variables only. That makes the most common experiment —
asking two models the same question — a restart and a lost conversation. Mastra's
`Agent` accepts `model` as a function of the request context, so per-request choice
is native and needs no rebuild. D6 has been rewritten accordingly; this milestone
makes the code match it.

**Why it sits between M1 and M2:** it changes the request path (web → proxy →
Mastra) that M1 just built, and M2's threads will persist messages. Better to settle
which model produced a message before there is a table full of them.

**Task numbering:** tasks here are `T1.5.1`, `T1.5.2`, … Do not confuse them with
M1's `T1.5` (streaming quality), which is complete.

---

## Tasks

### T1.5.1 — The allowlist

A server-side registry of selectable models. This is the security boundary and
everything else depends on it, so it comes first.

- **Do not invent model IDs.** Run
  `.agents/skills/mastra/scripts/provider-registry.mjs` and take the Anthropic
  entries from its output. Include current _and_ previous generations — the point is
  comparing them. Exclude anything the registry does not report as available.
- Each entry needs an id (the `provider/model` string), a display label, and enough
  metadata for the picker to group sensibly (family, generation).
- **There is no default.** A request that names no model is rejected like one that
  names an unknown model. A server-side default would be a second, invisible way to
  spend money — a client bug that drops the field would quietly bill the wrong model
  rather than fail. The picker owns the initial selection (T1.5.4).
- Resolution is by exact match against the registry. **Never** interpolate a
  client-supplied string into a model reference. The AI SDK's own reference
  implementation passes the request body's `model` straight to `streamText()`; that
  is demo code, and copying it would let any caller select the most expensive model
  on offer.
- Unit tests: a known id resolves; an unknown id is rejected; a request naming
  nothing is rejected rather than defaulted; the rejection does not echo an unbounded
  client string.

### T1.5.2 — Reject an unnamed or unknown model at the chat route

_Rewritten after implementation. The original plan put the decision in the agent's
`model` callback, reading the choice from the request context. That was wrong twice
over — see the PROGRESS.md entry for the evidence._

- Validate the request body's `model` in a Hono middleware scoped to `/chat/*`,
  resolving through T1.5.1's allowlist. Unknown model → 400. No model → 400. Neither
  reaches the provider. `AGENT_GENERAL_MODEL` becomes unused and is removed from
  `env.ts`, `.env.example` and the CI workflow.
- **It has to be middleware, not the agent.** `chatRoute` spreads leftover body
  fields into `agent.stream()`, and `model` there is a documented request-scoped
  override — so a body field reaches the provider without the agent's `model` ever
  being consulted. Validating inside the agent would guard a door the request walks
  past. Proved with curl against a running server.
- **Clone the body before reading it.** `await c.req.json()` in middleware consumes
  the one-shot request stream and leaves the route handler with nothing, turning
  every valid request into a bare 500. Use `c.req.raw.clone().json()`.
- The agent keeps a real model (`anthropic/claude-haiku-4-5`, resolved through the
  allowlist so a removed id fails at boot). It is not what the app runs on — every
  request overrides it — but Studio reads it to describe the agent, and a throwing
  callback there makes the agent undescribable.
- **Read the embedded docs first** —
  `node_modules/@mastra/core/dist/docs/references/reference-agents-agent.md` for the
  `model` field, `reference-agents-getLLM.md` for the override, and
  `docs-server-middleware.md` for the middleware shape.
- Unit-test the handler directly, with a **real `Request`** as `c.req.raw` — real
  one-shot body semantics, no Hono dependency to break when Mastra bumps it. Two
  tests: the body is still readable afterwards, and a disallowed model gets a 400
  instead of `next()`. Wording belongs to `models.test.ts`. Mutate the clone and the
  guard — each must fail exactly one.
- **Check Studio by hand, in a browser.** Not by curling its API — the failure mode
  is a rendered "Agent not found", which a 200 on one endpoint will not reveal.

### T1.5.3 — Carry the choice through the proxy

- The SvelteKit proxy forwards the model the client asked for. It does **not**
  validate, choose, or default — that logic lives in the Mastra server, and the proxy
  stays dumb (see M1's T1.3 note; that rule is not being relaxed).
- Test: the field survives the hop; a request without it still works.

### T1.5.4 — The picker

- Lives in the **composer footer**, following the AI Elements `PromptInput` layout: a
  model dropdown sitting on the same row as the send button, below the textarea.
- The Svelte port is ours to write — AI Elements is a React registry and was already
  rejected for this project (see the M1 decision log). Match the arrangement, not the
  code.
- The selection is sent per message, alongside the text, exactly as AI Elements does:
  `sendMessage({ text }, { body: { model } })`.
- The list comes from the server's allowlist, not a hardcoded array in the component
  — one source of truth, and the picker cannot offer something the server will
  reject.
- **The picker owns the initial selection**, because the server has no default. First
  visit selects **Haiku 4.5** — cheapest of the nine, so an accidental send costs the
  least. Every send carries a model.
- The choice persists across messages and survives a page reload, held in browser
  storage. Whether it persists per-thread is an **M2** question; do not build it here.
- Component tests: the list renders from the supplied models; choosing one changes
  what the next send carries; keyboard navigation works.

### T1.5.5 — A scripted model for the E2E

The value here is removing hand-written protocol from the test suite. Today
`tests/e2e/chat-stream.spec.ts` patches `window.fetch` and writes Mastra's SSE frames
by hand — roughly fifty lines encoding a protocol we do not own, which will drift
silently and leave the test green while the app breaks.

- Register a scripted model in the allowlist, built on `MockLanguageModelV3` from
  `ai/test` with output from `simulateReadableStream({ chunks, chunkDelayInMs })`.
  **Note:** the M1 plan's `MockLanguageModelV2` is stale — the installed `ai` ships
  V3 and V4 only.
- **Gate it.** It registers only when an explicit environment flag is set. A
  production process must not be able to select it. Test that the flag off means the
  id does not resolve.
- `playwright.config.ts`'s `webServer` currently starts `apps/web` only. Add the
  Mastra server, with the flag set.
- Rewrite `chat-stream.spec.ts` against it: delete `stubChat`, keep `ask`,
  `distanceFromBottom`, and the three existing tests. Assertions stay **event-based**
  (`toContainText('Paragraph 40')`), never clock-based, so the loss of
  `window.__chat.emit()`'s precise control costs nothing in stability.
- **Have the script call `getCurrentTime` in at least one test.** M1 dropped its
  agent–tool integration test as a test of Mastra rather than of us; this is where
  that coverage lands instead, at the level where a missing registration or a blank
  description shows up as the agent failing to answer.
- **Re-run the mutations from the M1 decision log** — remove the `scroll` listener,
  then drop the `if (pinned)` guard. Each must fail exactly the one test it failed
  before. A rewritten test that no longer catches the bug it was written for is not a
  rewrite, it is a deletion.

## Definition of Done

Performed manually in a browser:

1. The composer footer shows a model picker listing several Anthropic models.
2. Ask the same question twice with two different models selected → both answer, and
   the answers are visibly the work of different models.
3. Reload the page → the last selection is still there.
4. Send a request naming a model outside the allowlist, and one naming no model at
   all (curl the proxy directly) → both rejected with a readable error, and no
   upstream call is made.
5. `bunx playwright test` passes with the stub gone and Mastra running for real.
6. Both mutations from T1.5.5 still fail exactly one test each.
7. `bun run verify` passes, including coverage thresholds.

## Notes for the executing agent

- **The allowlist is the whole point of the security story.** If a task tempts you to
  let a client string reach a provider unchecked, that is the wrong task.
- Do not build per-thread model memory, model metadata columns, or a cost display.
  M2 owns persistence; nothing here should anticipate it.
- The existing `chat-stream.spec.ts` is green and mutation-proven. Keep it working
  until T1.5.5 replaces it, and do not merge a state where neither exists.
